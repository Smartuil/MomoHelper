## 1. 背景与产品定位

### 1.1 背景

墨墨背单词已经提供了成熟的复习调度、学习计划与背词执行能力，但用户在学习过程中仍存在明显的「认知盲区」：

- 只知道今天忘了哪些词，不知道**为什么忘**。
- 大量单词「长得像、拼写接近、含义不同」，反复混淆却缺少针对性诊断。
- 释义、例句、助记需要用户自己写，成本高，很多人干脆不写。
- 缺乏可回溯的学习趋势与复盘视角。

### 1.2 产品定位

本产品**不是再造一个背单词 App**，而是贴着墨墨工作流的一层 **AI 学习副驾（Study Copilot）**：

```text
墨墨                AI 学习副驾
──────────────────────────────────────────
复习调度            学习诊断
学习计划      ←     内容增强
背词执行            生词整理 / 易混词分析
认识/模糊/忘记      复盘建议
```

职责边界：

- 墨墨负责**学习执行**：复习调度、认识/模糊/忘记的判定、记忆曲线。
- AI 副驾负责**诊断、整理、增强、复盘**，不介入判定环节。

### 1.3 产品目标

| 目标 | 说明 | 可度量指标 |
| --- | --- | --- |
| G1 提升复习效率 | 让用户把时间花在真正记不住的词上 | 每周写入自定义内容条数、顽固词本词数 |
| G2 降低内容创作成本 | 释义/例句/助记由 AI 生成并回写墨墨 | 生成内容采纳率（写入/生成） |
| G3 提供诊断视角 | 让用户知道「为什么忘」和「和谁混」 | 易混词组诊断次数、诊断结果加入词本转化率 |
| G4 建立复盘习惯 | 每日复盘 + 周期性报告 | 复盘查看率、周报打开率 |

### 1.4 非目标（第一阶段明确不做）

- 记忆卡（`/api/v1/markji/` 全线）
- 浏览器插件划词、当前网页生词提取
- PDF 导入与解析
- OCR 拍照识词
- 独立背词系统（不替代墨墨 App 的背词流程）
- 模拟用户在墨墨中的「认识 / 模糊 / 忘记」操作
- 复杂的长期学习画像、多端同步的个人词汇知识库

## 2. 用户与使用场景

### 2.1 目标用户

| 用户类型 | 特征 | 核心诉求 |
| --- | --- | --- |
| 备考型学习者 | 考研 / 托福 / 雅思 / GRE，词量大、时间紧 | 快速识别顽固词、易混词，批量生成助记 |
| 职场提升型 | 工作场景英语，有明确语境需求 | 工作/技术语境释义与例句 |
| 泛学习型 | 长期使用墨墨，稳定打卡 | 每日复盘、进度可视化、趋势报告 |

### 2.2 核心用户旅程（MVP 闭环）

```text
1. 绑定墨墨 Token
2. 打开今日看板，看到进度 / 遗忘词 / 未完成词
3. 针对遗忘词发起 AI 诊断（遗忘原因 + 形近词 / 易混词）
4. 生成释义 / 例句 / 助记，回写墨墨
5. 把诊断出的词加入云词本或学习计划
6. 回到墨墨完成复习
```

这条闭环是 MVP 的验收基准：**任何一步断开，MVP 不成立。**

### 2.3 典型使用场景

| 场景 | 承载端 | 触发方式 |
| --- | --- | --- |
| 每天睡前看今日完成情况与最易忘的词 | 小程序 | 每日主动打开 |
| 周日整理本周易混词组，批量生成对比助记 | Web | 周期性 |
| 读到一篇英文文章，粘贴进来看有哪些值得背的词 | Web / 小程序 | 内容驱动 |
| 背到某个词想不起来，随手问 AI | 小程序 | 即时 |
| 发现最近遗忘暴增，检查是否需要降低新词量 | Web | 异常驱动 |

## 3. 能力边界与约束（需求前提）

以下约束来自 `docs/api-capability-gap.md`，是**需求设计的前提条件**，不是可选项。

### 3.1 可用的墨墨 API 能力

- 查询单词拼写与 `voc_id` 的映射（`vocabulary` / `vocabulary/query`）
- 今日学习进度（`study/get_study_progress`）
- 今日学习单词、未完成词（`study/get_today_items`）
- 学习记录、复习计划、顽固词标签（`study/query_study_records`）
- 云词本的创建 / 更新 / 删除 / 查询（`notepads` 系列）
- 加入学习计划（`study/add_words`，单次上限 1000）
- 提前复习（`study/advance_study`，需账号等级 ≥ 10）
- 自定义释义 / 例句 / 助记的读取与写入（`interpretations` / `phrases` / `notes`）
- AI 内容生成（平台侧 `packages/ai`）

### 3.2 硬约束清单

| 编号 | 约束 | 需求影响 |
| --- | --- | --- |
| C1 | 无官方词典内容，三类内容接口只返回**用户自己创建**的内容 | AI 生成属于从零创作，不依赖官方词库改写 |
| C2 | 学习数据接口处于**公测**，需用户在 App 开启自动同步，当日未打开 App 无法准确计算 | 所有学习数据功能**必须**设计降级路径 |
| C3 | 无按天历史序列，仅有今日快照 + 单词级当前状态 | 趋势类功能必须由平台**每日留存快照** |
| C4 | 释义 + 例句 + 助记**合计每天最多 600 条** | 批量生成必须是**分天任务队列**，支持断点续传 |
| C5 | `advance_study` 需账号等级 ≥ 10，且**无等级查询接口** | 不可无条件承诺；失败后处理；优先用 `add_words` 的 `advance` |
| C6 | 无音标、词频、词根、形近词数据 | 易混词 / 词根分析由 AI + 本地算法（编辑距离）推断 |
| C7 | 只支持向学习计划**添加**单词，不支持移除 | 计划调整需通过墨墨 App 完成 |
| C8 | 不支持删除云词本中**单个**单词 | 需 GET 全量 → 修改 → 整体覆盖提交 |
| C9 | 请求频控：10 秒 20 次 / 60 秒 40 次 / 5 小时 2000 次 | 后端统一限流，禁止前端直连 |
| C10 | Token 有效期 7 天，无刷新机制 | 需过期提醒 + 重新绑定引导 |
| C11 | 更新云词本要求**全字段必填**，并发写会互相覆盖 | 需乐观锁 / 串行化 |
| C12 | 查不到 ≠ 报错（`success: true` 但 `data.voc` 不存在） | 单词存在性判断**必须**判 `data.voc` |
| C13 | 云词本 `content` 可能是不规范内容 | 解析必须容错 |
| C14 | 日期字段按 UTC+8 日期边界存储 | 展示前需统一转换 |

## 4. 产品形态与端策略

| 形态 | 定位 | 承载能力 |
| --- | --- | --- |
| **Web 工作台** | 复杂操作、长文本、批量管理、数据分析 | 学习数据分析、遗忘词诊断、易混词分析、云词本管理、文本生词提取、批量生成、周期报告 |
| **微信小程序** | 轻量、随身、每日打开 | 今日进度、今日遗忘词、AI 问词、易混词解释、每日复盘、手动加词、粘贴提取、一键加词本/计划 |

端策略原则：

- 重分析、重输入、重批量 → Web。
- 高频、短时、即用即走 → 小程序。
- 业务逻辑下沉到 `packages/*`，两端复用，避免各写一套。

## 5. 功能需求（FR）

> 每个模块包含：元信息表（优先级 / 承载端 / API 依赖）+ 需求条目 + 验收标准（关键条目）。
> 未标注验收标准的一般条目，默认以「可操作、有明确成功/失败反馈、失败有可读错误」为验收基线。

### FR-1 账号与墨墨连接

| 项 | 内容 |
| --- | --- |
| 优先级 | **P0** |
| 承载端 | 两端（复杂管理在 Web） |
| API 依赖 | 任一鉴权接口（用于校验 Token） |
| 约束 | C10 |

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-1.1 | 绑定墨墨 Open API Token：用户粘贴 Token 后保存并加密存储 | P0 |
| FR-1.2 | 检查 Token 是否有效（调用鉴权接口，识别 401 / `common_unauthorized`） | P0 |
| FR-1.3 | 展示 Token 状态与过期提醒（有效期 7 天，到期前提示重新绑定） | P0 |
| FR-1.4 | 手动刷新学习数据（刷新今日进度与今日词表） | P0 |
| FR-1.5 | AI 写入权限总开关 | P0 |
| FR-1.6 | 分项写入权限：自定义释义 / 例句 / 助记 / 云词本 / 学习计划 | P0 |
| FR-1.7 | 解绑 / 重新绑定 Token，解绑时可选择清除平台侧数据 | P0 |

**验收标准**

- AC-1.1：输入有效 Token，保存成功后状态为「已连接」，且 Token 明文不出现在前端可读位置（仅后端可解密）。
- AC-1.2：输入无效 Token，返回明确错误（非 500），且不落库。
- AC-1.3：写入类操作在未开启对应权限时被拒绝，并给出「请在设置中开启」的提示。
- AC-1.4：Token 剩余有效期 ≤ 1 天时，两端均展示过期提醒。

- AC-2.4：所有日期展示按北京时间（UTC+8）渲染（C14）。

### FR-3 遗忘词分析

| 项 | 内容 |
| --- | --- |
| 优先级 | **今日遗忘词 = P0，其余 = P1/P2** |
| 承载端 | Web 深度分析 / 小程序轻量查看 |
| API 依赖 | `study/get_today_items`、`study/query_study_records`、`study/advance_study`、`notepads` |
| 约束 | C2、C3、C5、C6 |

| 编号 | 需求 | 优先级 | 说明 / 降级 |
| --- | --- | --- | --- |
| FR-3.1 | 今日遗忘词列表 | P0 | 直接可取自今日词表 |
| FR-3.2 | 最近 7 天遗忘词 | P1 | 无历史事件流，用 `last_study_date` ∈ 区间 且 `last_response = FORGET` **近似**；UI 需说明「可能漏掉期间遗忘但已记住的词」 |
| FR-3.3 | 最近 30 天遗忘词 | P1 | 同 FR-3.2 |
| FR-3.4 | 高频遗忘词 | P1 | API 无遗忘次数；用官方 `STICKING` 标签替代，或平台逐日累积计数（见 FR-15.5） |
| FR-3.5 | 顽固词识别 | P0 | `query_study_records` 过滤 `tags` 含 `STICKING` |
| FR-3.6 | 遗忘原因推测 | P1 | AI 推断，原因枚举见下 |
| FR-3.7 | 按遗忘原因分类 | P1 | 基于 FR-3.6 的分类结果聚合 |
| FR-3.8 | 为每个遗忘词生成补救建议 | P1 | AI 生成，建议可直接触发释义/例句/助记生成 |
| FR-3.9 | 将遗忘词加入「顽固词本」 | P1 | 依赖 FR-9 云词本能力 |
| FR-3.10 | 对遗忘词执行提前复习 | P2 | 受 C5 限制；失败时提示等级不足并引导改用「加词并立即复习」 |

**遗忘原因枚举**（AI 推断输出，需固定枚举以支持分类统计）

```text
SPELLING_SIMILAR    拼写相似
ABSTRACT_MEANING    词义抽象
RARE_SENSE          熟词僻义
CN_MEANING_CONFLICT 中文释义混淆
COLLOCATION_WEAK    搭配不熟
ROOT_DIVERGENCE     词根相同但含义分叉
LACK_CONTEXT        缺少真实语境
```

**验收标准**

- AC-3.1：今日遗忘词数量与 `get_today_items` 中 `first_response = FORGET` 的条目一致。
- AC-3.2：近 7 天 / 30 天结果页必须显式标注「近似统计」及原因。
- AC-3.3：FR-3.10 调用失败时，错误提示区分「等级不足」与「接口不可用」两种情况。

### FR-4 相似词与易混词诊断（核心）

| 项 | 内容 |
| --- | --- |
| 优先级 | **P0** |
| 承载端 | Web 完整诊断台 / 小程序随身速查 |
| API 依赖 | `vocabulary` 系列、`notepads`、`notes`、`phrases` |
| 约束 | C1、C6 |

**定位**：解决用户经常混淆「长得像、拼写接近、含义不同」的单词的问题，是本产品的差异化核心。

| 编号 | 需求 | 优先级 | 实现方式 |
| --- | --- | --- | --- |
| FR-4.1 | 根据遗忘词自动发现形近词 | P0 | 本地编辑距离 + 已知词集合两两计算 |
| FR-4.2 | 识别只差一个字母的词 | P0 | 编辑距离 = 1 |
| FR-4.3 | 识别拼写高度相似的词 | P0 | 编辑距离阈值 / 相似度评分 |
| FR-4.4 | 识别同词根但意思不同的词 | P1 | 纯 AI 推测（无词根数据） |
| FR-4.5 | 识别中文释义接近但英文用法不同的词 | P1 | AI 生成释义后比对 |
| FR-4.6 | 识别发音接近但拼写不同的词 | P2 | 无音标数据，AI 推测 |
| FR-4.7 | 生成易混词对比解释 | P0 | AI |
| FR-4.8 | 生成最小对比例句 | P0 | AI |
| FR-4.9 | 生成「别再混」记忆提示 | P1 | AI，短句形式 |
| FR-4.10 | 将易混词组加入云词本 | P0 | `notepads` |
| FR-4.11 | 为易混词写入自定义助记或例句 | P1 | `notes` / `phrases` |

**约束说明**：单词接口无法列举全部词，形近词发现只能针对**已知词集合**（今日词、学习记录、用户词本）两两计算，需在 UI 中说明覆盖范围。

**示例词组**（用于测试与示例）

```text
adapt / adopt / adept
affect / effect
principal / principle
stationary / stationery
complement / compliment
moral / morale
economic / economical
```

**验收标准**

- AC-4.1：对 `affect / effect` 这类典型对照，能给出拼写差异位置的可视化标注。
- AC-4.2：诊断结果可一键加入云词本；加入后云词本内容正确（需容忍 C13 的容错解析）。
- AC-4.3：形近词结果页标注计算范围（「基于你的 N 个已知词」）。

### FR-5 AI 问词助手

| 项 | 内容 |
| --- | --- |

### FR-16 学习词汇词云

| 项 | 内容 |
| --- | --- |
| 优先级 | **P1（基础）/ P2（扩展）** |
| 承载端 | Web 为主，小程序轻量版 |
| API 依赖 | `study/get_today_items`、`study/query_study_records`、`notepads` + 平台累积的 `forget_events` |
| 约束 | C2、C3、C6 |

**定位**：用可视化让用户一眼看出词汇的分布特征。**同一批词支持切换不同视角重新度量**——字号代表当前视角的主维度，颜色代表词的状态或所属分组。

#### 视角定义

| 视角 | 字号映射（越大概率越高） | 布局 | 颜色映射 | 数据来源 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| **难度视角**（默认） | 遗忘强度 | 平铺 | 词状态 | `forget_events`（FR-15.5）+ `STICKING` + `study_count` 兜底 | P1 |
| **进度视角** | 学习次数 `study_count` | 平铺 | 词状态 | `query_study_records` | P1 |
| **结构视角** | 组内学习权重 | 按分组聚集 | 所属分组 | 首字母（直接）/ 主题（AI）/ 词根（AI 推测） | P2 |

设计约束：**切换视角时颜色语义尽量保持不变**（仅结构视角按分组着色），避免用户心智模型被打乱。

#### 需求条目

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-16.1 | 词云基础渲染：字号映射、颜色映射、悬停详情 | P1 |
| FR-16.2 | 难度视角：字号 = 遗忘强度 | P1 |
| FR-16.3 | 进度视角：字号 = 学习次数 | P1 |
| FR-16.4 | 视角切换控件；切换时保留时间范围等筛选状态 | P1 |
| FR-16.5 | 每个视角独立展示图例（字号含义 + 颜色含义） | P1 |
| FR-16.6 | 时间范围切换：今日 / 最近 7 天 / 最近 30 天 / 全部 | P1 |
| FR-16.7 | 颜色区分词状态：新词 / 复习词 / 今日遗忘 / 未完成 / 顽固词 | P1 |
| FR-16.8 | 点击任意词进入 AI 问词（FR-5）或易混词诊断（FR-4） | P1 |
| FR-16.9 | 圈选多个词后批量操作：加入云词本 / 生成释义助记（复用 FR-6~FR-9） | P1 |
| FR-16.10 | 结构视角：按首字母分组 | P2 |
| FR-16.11 | 结构视角：按主题分组（依赖 AI 分类，复用 FR-10 能力） | P2 |
| FR-16.12 | 结构视角：按词根分组（AI 推测，UI 必须标注） | P2 |
| FR-16.13 | 云词本词云（按指定词本渲染） | P2 |
| FR-16.14 | 生词提取结果词云（FR-10 候选词可视化） | P2 |
| FR-16.15 | 小程序轻量版（Top N 词 + 简化交互） | P2 |

#### 各视角的权重来源

**难度视角**

| 权重源 | 可用性 | 说明 |
| --- | --- | --- |
| 平台累积遗忘次数 | 依赖 FR-15.5 | 最准确，反映真实遗忘强度 |
| `tags` 含 `STICKING` | 直接可用 | 官方顽固词标记，强权重 |
| `study_count` | 直接可用 | 「每日最多计入 1 次」，颗粒度粗，作为兜底 |
| `first_response = FORGET` / `last_response = FORGET` | 直接可用 | 二值权重，用于临时高亮 |

**进度视角**

| 权重源 | 可用性 | 说明 |
| --- | --- | --- |
| `study_count` | 直接可用 | 主维度 |
| `first_study_date` → `last_study_date` 跨度 | 直接可用 | 辅助维度，学习周期越长越突出 |

**结构视角**

| 分组维度 | 可用性 | 说明 |
| --- | --- | --- |
| 首字母 | 直接可用，零成本 | 不依赖 AI，建议作为结构视角的默认分组 |
| 主题 | 依赖 AI 分类 | 复用 FR-10 的分类能力 |
| 词根 | AI 推测，不可靠 | 无词根数据（C6），UI 必须标注「推测」 |

**验收标准**

- AC-16.1：词云必须标注数据范围与统计口径（如「基于最近 30 天的学习记录，共 762 词」），不得让用户误以为是全量词汇。
- AC-16.2：每个视角必须显示自己的图例，明确「字号代表什么、颜色代表什么」。
- AC-16.3：切换视角时保留时间范围与筛选状态，不回到默认值。
- AC-16.4：权重口径可解释——悬停或点击任一词能看到「为什么这个词这么大」。
- AC-16.5：词数超过 200 时自动截断为 Top N，并提示「仅显示权重最高的 N 个词」。
- AC-16.6：数据不可用（公测接口失败）时降级为上次缓存结果并标注时间（C2）。

**边界说明**

- 墨墨 API 无法列举用户全量词汇，词云只能基于**已知词集合**（今日词表 / 学习记录查询结果 / 云词本）渲染，覆盖范围必须在 UI 中说明。
- 墨墨 API 不提供词频、难度、大纲标记等任何数据，字号完全来自平台侧推断（C6）。
- 真实遗忘强度依赖平台逐日累积（FR-15.5）；累积不足时退化为 `STICKING` + `study_count` 组合权重。

### 8.1 墨墨 Token 的存储与密钥管理（对应 FR-1.1）

Token 分三层存放，任一层单独泄露都不足以还原明文：

| 内容 | 存放位置 | 说明 |
| --- | --- | --- |
| 密文 + IV + authTag | PostgreSQL `maimemo_credentials` | 唯一持久化落点；随库备份、可迁移 |
| 加密主密钥 | 服务器 `.env`（权限 `600`）/ 腾讯云 SSM 凭据管理 | 与数据库物理分离，不写入代码仓库、不写入数据库备份 |
| 明文 Token | 仅后端进程内存 | 请求结束即释放；不落盘、不进日志、不下发前端 |

`maimemo_credentials` 细化字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `user_id` | uuid | 主键 |
| `credential_type` | text | `MANUAL`（个人 token 粘贴）/ `OIDC`（开放平台授权登录），现阶段仅 `MANUAL` |
| `ciphertext` | text | AES-256-GCM 密文（base64） |
| `iv` | text | 12 字节随机 nonce，每次写入重新生成 |
| `auth_tag` | text | 16 字节认证标签 |
| `refresh_ciphertext` | text null | refresh token 密文，仅 `OIDC` 使用，用于静默续期，解决 C10 的 7 天重绑摩擦 |
| `refresh_iv` / `refresh_auth_tag` | text null | 仅 `OIDC` |
| `key_version` | int | 支持密钥轮换，新旧密钥共存，避免全表重加密 |
| `token_status` | text | `ACTIVE` / `EXPIRED` / `INVALID` |
| `token_expires_at` | timestamp | `MANUAL` 按 7 天有效期记录（C10），用于 FR-1.3 过期提醒；`OIDC` 记录 access token 过期时间，refresh 后更新 |
| `last_verified_at` | timestamp | 最近一次校验成功时间 |
| `created_at` / `updated_at` | timestamp | — |

实现约束：

- 加密算法固定为 AES-256-GCM；每次写入生成新 IV；AAD 为 `user_id + 用途`（access / refresh 各自独立），防止密文被跨用户或跨字段替换。
- OIDC 路径为预留设计（接入墨墨开放平台后启用）：refresh 失败即标记 `EXPIRED` 并引导重新授权，不自动重试；refresh token 明文与密文不落日志、不下发前端。
- 加解密函数只允许在服务器 Node 进程内调用，封装在 `packages/core`（后端专用入口），前端与小程序不得引入。
- 未通过 FR-1.2 有效性校验的 Token **不落库**（对应 AC-1.2）。
- 解绑时物理删除该行（对应 FR-1.7）。
- 明确排除的方案：前端 `localStorage` / 小程序 Storage（违反 NFR-2.2）；明文写入磁盘或数据库；主密钥与密文同处一地。

**数据留存原则**

- 快照与事件累积类数据为平台核心资产，不可被 Token 解绑自动清空（需用户显式选择）。
- AI 生成记录用于质量评估与成本核算，保留期可配置。

## 9. 技术约束与实现依赖

- 架构：monorepo（`apps/web`、`apps/miniprogram`、`apps/server`、`packages/*`）。
- 后端：独立服务器上运行 Node.js 24 单进程（Hono + Zod），承载 HTTP API、队列 Worker 与定时任务。
- 接入层：Nginx 负责 TLS、静态资源、反向代理与限流，不承载业务逻辑。
- 墨墨封装：`packages/maimemo`，**以真机实测为准**，不以 `memo-api` 技能文档为准（该文档已发现 4 处与线上不符）。
- AI 封装：`packages/ai`，由服务器直连 DeepSeek。
- 数据库：PostgreSQL 18 本机自建（宝塔既有实例，Drizzle）。
- 部署：全部业务在独立服务器（2 核 1G + 1G swap + 200Mbps），不使用 EdgeOne（详见 9.1 与 `architecture.md`）。
- 关键实现细节（必须遵守）：
  - 响应统一包裹在 `data` 中。
  - `Vocabulary` 只有 `id` 与 `spelling`。
  - `StudyRecord.tags` 为字符串数组。
  - `voc_id` 形如 `voc-<约 80 字符>`，`notepad id` 形如 `np-<约 60 字符>`，**不做格式假设**。
  - `advance_study` 无等级预检接口，只能失败后处理。

### 9.1 部署分工（已确认）

运行环境为单台独立服务器（腾讯云轻量 2 核 1G + 1G swap + 200Mbps 不限流量，OpenCloudOS 9.4 + 宝塔面板），**不使用 EdgeOne**。

| 能力 | 落点 | 理由 |
| --- | --- | --- |
| TLS 终结 / 静态资源 / 反向代理 / 限流 | Nginx（宿主机） | 不承载业务逻辑，只做接入 |
| HTTP API（鉴权 / 数据 / AI / 墨墨代理） | Node 单进程 | 业务唯一入口 |
| 墨墨 API 出口 | Node 单进程 | C9 频控是账号级，出口唯一才能集中限流 |
| Token 加解密 | Node 单进程 | 密钥只在一处 |
| 写入队列 Worker | Node 单进程（并发 1） | C4 配额单点记账 |
| 定时任务（快照 / 续跑 / 报告 / Token 巡检） | Node 单进程（node-cron） | 需要常驻进程 |
| AI 调用（交互式 + 批量） | Node 单进程直连 DeepSeek | 国内直连无网络问题，无需边缘代理 |
| PostgreSQL 18 | 服务器本机（宝塔实例，127.0.0.1） | 与 Worker 同机延迟最低，免容器省内存 |
| Redis | **不部署** | 单进程单出口，限流计数放进程内存即可 |

设计原则：

1. **墨墨 API 出口唯一**。所有墨墨调用只从这一个进程发出，`packages/maimemo` 仅在此运行。这是 C9 成立的前提——多出口会导致各自的限流计数器都不超限，合计却超限。
2. **配额记账唯一**。C4 的 600 条/天必须单点记账，避免并发任务超额写入。
3. **Token 解密唯一**。主密钥只配置在一处，不分散到多个运行环境。
4. **单进程承载三模块**。2 核 1G 规格下拆多进程只浪费内存；必须实现优雅关闭（先停 Scheduler，等 Worker 完成当前任务，再关 HTTP）。
5. **不引入 Redis 与消息队列中间件**。任务量与并发度都用不上；需要时再引入，迁移成本低。

资源预算、部署步骤、PostgreSQL 调参、编码约定见 `docs/architecture.md`。
