# 墨墨开放 API 能力核对与缺口

本文记录墨墨开放 API 的真实能力边界，以及在功能设计上需要承担的额外成本。结论全部基于接口规范原文核对，不依赖二手摘要。

## 核对来源

| 来源 | 地址 | 性质 |
| --- | --- | --- |
| OpenAPI 规范 | `https://open.maimemo.com/api_bundle.yaml` | 权威数据源，`open.maimemo.com` 文档站的前端数据 |
| 官方功能说明 | `https://memodocs.maimemo.com/docs/PNvOw2E1AivPtlkRlQgce1W1n2c` | 功能概览，非接口级清单 |
| 官方在线演示 | `https://www.maimemo.com/pages/openapi-demo/` | 覆盖全部 34 个操作的交互演示 |
| 本地技能文档 | `.codebuddy/skills/memo-api/` | 接口参数与用法说明 |

核对时间：2026-09-20。

需要注意：官方功能说明中的「调取墨墨词库的单词释义、例句、助记内容」是宣传口径，实际接口只能读取**用户自己创建**的内容，容易产生误解，详见第三节。

当前阶段明确不做记忆卡，因此不在实现范围内。如果后续要接入，需要重新评估本节以外的内容。

## 二、字段级核对

### 单词接口只返回 ID 和拼写

`Vocabulary` 是整个规范中唯一被单词接口使用的返回结构，只有两个字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 单词 ID |
| `spelling` | string | 拼写 |

规范全文中检索不到**音标、词频、词根、难度、考试大纲标记**等任何字段。上述数据墨墨开放 API 一律不提供。

`Vocabulary` 的定义在规范中标注为「暂无文档」，字段信息来自 schema 本身。

### 三类内容接口都限定「自己创建的」

规范中三个读接口的描述原文：

| 接口 | 描述原文 |
| --- | --- |
| `GET /memo/interpretations` | 获取单词下**自己创建的**释义 |
| `GET /memo/notes` | 获取单词下**自己创建的**助记 |
| `GET /memo/phrases` | 获取单词下**自己创建的**例句 |

含义是：读不到墨墨官方词库内容，只能读到当前凭证用户自己上传的内容。对于没有写过自定义内容的新用户，这三个接口返回的是空数组。

### 学习数据的可用字段

`StudyProgress`（今日进度，单点快照）：

| 字段 | 说明 |
| --- | --- |
| `finished` | 已完成的单词数 |
| `total` | 今日应完成的单词数 |
| `study_time` | 今日学习时长，毫秒 |

`StudyTodayItem`（今日单词）：`voc_id`、`voc_spelling`、`order`、`first_response`、`is_new`、`is_finished`。

`StudyRecord`（单词级记录）：`voc_id`、`voc_spelling`、`add_date`、`first_study_date`、`last_study_date`、`next_study_date`、`last_response`、`study_count`、`tags`。

其中 `study_count` 的描述为「学习次数（每日最多计入 1 次）」，`tags` 为字符串数组，元素取值为 `STICKING` 或 `WELL_FAMILIAR`，实测中大多数单词为空数组。

**关键结论**：所有学习数据字段都是「当前状态」或「单词级累计」，没有任何按天的学习量、时长或正确率序列。也没有逐次作答明细，只有 `first_response`（今日首次）和 `last_response`（最后一次）。

## 三、能力可行性矩阵

以 `Maimemo-AI-Study-Copilot-Features.md` 的功能清单为准。

### 可直接实现

| 功能 | 依据 |
| --- | --- |
| 绑定与校验 Token | 任一接口的鉴权响应 |
| 今日目标、已完成、剩余、时长、完成率 | `get_study_progress` |
| 今日新词、复习词、未完成词 | `get_today_items` 配合 `is_new`、`is_finished` |
| 今日遗忘词 | `is_finished: true` 后过滤 `first_response = FORGET` |
| 顽固词识别 | `query_study_records` 过滤 `tags = STICKING` |
| 顽固词入云词本 | `POST /notepads` |
| 计划总词数、未来复习压力 | `query_study_records` 的 `as_count` 与 `next_study_date` 区间 |
| 批量查词是否在墨墨词库 | `vocabulary/query`，返回为空即不在词库 |
| 批量加入学习计划 | `add_words`，单次上限 1000 |
| 添加单词并立即复习 | `add_words` 的 `advance` |
| 云词本创建、更新、删除 | `notepads` 系列接口 |
| AI 问词、释义、例句、助记的生成与写入 | AI 加三类内容接口 |
| 每日复盘 | 今日数据聚合加 AI |
| 小程序轻量功能 | 上述能力的子集 |

### 需要变通或降级

| 功能 | 问题与变通方式 |
| --- | --- |
| 最近 7 天 / 30 天遗忘词 | 无历史事件流。只能按 `last_study_date` 落在区间且 `last_response = FORGET` 近似，会漏掉「期间遗忘过但最后记住了」的词 |
| 高频遗忘词 | 无遗忘次数统计。只能用官方 `STICKING` 标签替代，或平台自行逐日累积计数 |
| 自动发现形近词、拼写高相似词 | 无相似词接口，需本地编辑距离算法；且单词接口无法列举全部词，只能对已知词集合两两计算 |
| 识别中文释义接近、发音接近 | 无官方释义与音标数据，只能靠 AI 生成后比对 |
| 识别同词根但含义分叉 | 无词根数据，纯 AI 推测 |
| 合并词本、拆分词本 | 无原子接口，需 GET 后拼接 `content` 再整体覆盖提交，且更新接口要求全字段必填 |
| 批量生成释义、例句、助记 | 无批量写接口，且受 600 条/天的硬配额约束，必须分天执行 |
| 遗忘词提前复习 | 受账号等级 10 以上限制，无法无条件承诺 |
| 词本打标签 | `notepad.tags` 为自由字符串数组，规范未给出合法值枚举 |

### 无法实现

| 功能 | 原因 |
| --- | --- |
| 学习时长趋势、完成率趋势、遗忘词趋势 | API 无历史时间序列，只有今日快照与单词级当前状态 |
| 顽固词变化趋势 | 同上，需要平台自行留存快照后比较 |
| 跨周统计最常混淆的词组 | 无混淆事件数据源，只能靠平台累积 AI 诊断结果 |
| 从学习计划移除单词 | 无对应接口，只支持添加 |
| 删除云词本中的单个单词 | 无对应接口，只能整体覆盖 `content` |

## 四、硬约束清单

### 请求频控

规范原文：

- 10 秒 20 次
- 60 秒 40 次
- 5 小时 2000 次（墨墨背单词）
- 5 小时 8000 次（墨墨记忆卡）

### 内容创建频控

规范原文：

> 为了避免滥用和保证服务质量，每天最多创建 600 条内容（例句、助记、释义合并在内），若大量创建低质、无意义、违规内容可能则会被进一步限制。

这是对产品影响最大的一条约束：自定义释义、例句、助记**三类合计**每天最多 600 条。一份 500 词的词表如果同时生成这三类内容，共 1500 条，需要跨越 3 天才能写完。

因此「批量生成」必须设计为分天执行的任务队列，并具备断点续传、进度可视化和失败重试能力，不能做成一次性同步操作。

### 学习数据处于公测状态

规范标注为公测，且明确说明不保证可用性、需要用户开启自动同步、当日未打开 App 初始化时无法准确计算。所有依赖学习数据的功能都必须设计降级路径。

### 提前复习存在等级门槛

`advance_study` 需要账号等级 10 以上才能调用。规范中**没有**查询账号等级的接口，因此无法预检，只能在调用失败后处理。`add_words` 的 `advance` 参数不受此限制。

### Token 有效期

本地技能文档说明：通过网页端取得的 Token 有效期为 7 天，过期需要重新登录获取，接口不提供刷新机制。该说明未出现在规范文件中，实现前建议再次确认。

## 五、需要平台自行补齐的能力

1. **每日学习快照**。新增快照表，由定时任务每天调用 `get_study_progress` 留存一条记录。周报、月报和所有趋势类功能都依赖这张表，没有它这些功能无法实现。
2. **内容写入队列**。受 600 条/天配额约束，所有批量写入必须串行排队、按天分配额度，并记录已写条数。
3. **云词本的读改写保护**。更新接口是全字段覆盖，并发写入会互相覆盖，需要乐观锁或串行化处理。
4. **AI 推断层**。形近词、词根分析、遗忘原因等官方不提供的数据，需要由 AI 结合本地算法（如编辑距离）生成，成本和准确率需要单独评估。
5. **遗忘事件累积**。若要支持「高频遗忘词」和「最常混淆词组」，需要平台自己逐日累积，不能依赖 API。

## 六、对既有文档的修正

`Maimemo-AI-Study-Copilot-Features.md` 的能力边界原文为「查询单词与词库信息」，容易让人以为可以读取官方词典内容。现已修正为「查询单词拼写与 voc_id 的映射」，并补充了本节的能力缺口与约束摘要。

## 七、真机实测记录

实测时间：2026-09-20。账号为 2020 年注册的老账号，学习计划 8614 词，当日已完成 100/100。

本节内容全部来自真实响应，实现时以此为准，不以 `memo-api` 技能文档为准。

### 结论一：核心地基成立

| 验证项 | 实测结果 |
| --- | --- |
| 今日进度 | `finished=100`、`total=100`、`study_time=620708`（约 10.3 分钟） |
| 今日词表 | 100 条，其中 `FORGET=7`、`FAMILIAR=90`、`VAGUE=3`、`is_new=0` |
| 遗忘词能否取出 | 可以，稳定返回 7 条 |
| 计划总词数 | `count=8614` |
| 未来 7 天待复习 | `count=762` |
| 顽固词 | 1000 条记录中 `STICKING=19`、`WELL_FAMILIAR=81` |

今日看板、遗忘词分析、复习压力分析三项功能的数据来源全部可用。

### 结论二：三类内容接口确实只返回空

老账号实测 `interpretations`、`notes`、`phrases` 三个接口全部返回空数组。第二节中「只能读取用户自己创建的内容」得到实证。

### 结论三：响应有统一包裹层（技能文档未记载）

所有响应统一包裹在 `data` 中：

```json
{ "errors": [], "data": { "progress": { "finished": 100, "total": 100, "study_time": 620708 } }, "success": true }
```

鉴权失败时返回 HTTP 401，响应体为：

```json
{ "errors": [ { "code": "common_unauthorized", "msg": "Authorization failed", "info": "" } ], "success": false }
```

`memo-api` 技能文档中的所有示例都省略了这层包裹，直接写 `{ "progress": {...} }`。按技能文档编写解析逻辑会全部失败。

### 结论四：查不到不等于报错

查询一个不存在的拼写：

```json
{ "errors": [], "data": {}, "success": true }
```

返回 HTTP 200，`success` 仍为 `true`，`errors` 为空，只是 `data` 里没有 `voc` 字段。

因此判断单词是否存在于墨墨词库时，**不能依赖 `success` 或错误码，必须判断 `data.voc` 是否存在**。

### 结论五：字段与结构与技能文档不符

| 项目 | 技能文档 | 实测 |
| --- | --- | --- |
| `StudyRecord.tags` | 字符串，枚举 `STICKING` / `WELL_FAMILIAR` | **字符串数组**，多数为 `[]` |
| 云词本解析项 | `{ "type": "...", "data": { "chapter": "..." } }` | **扁平结构** `{ "type": "CHAPTER", "chapter": "单词列表" }` |
| `voc_id` 格式 | 32 位十六进制，如 `5a7BFf4F...` | 形如 `voc-<约 80 字符>` |
| 云词本 id 格式 | 未说明 | 形如 `np-<约 60 字符>` |

ID 的长度和格式不可做任何假设。

### 结论六：时间语义

`next_study_date` 实测值形如 `2027-07-04T16:00:00.000Z`，实际表示北京时间 2027-07-05 00:00。日期字段按 UTC+8 的日期边界存储，展示前需要转换。

### 结论七：云词本内容可能不规范

实测唯一一个云词本的 `content` 为 `" 兔兔"`，是用户手工输入的非词表内容，解析结果只有一个 `CHAPTER` 项（`单词列表`），没有 `WORD` 项。

说明云词本的 `content` 需要做容错解析，不能假设一定是规范的一行一词格式。

### 技能文档可靠性提醒

本次实测共发现 `memo-api` 技能文档 4 处与线上不符（响应包裹层缺失、`tags` 类型错误、解析结构错误、ID 格式过时）。该技能是人工整理的摘要，**不能作为实现的唯一依据**。

建议在 `packages/maimemo` 中建立类型定义时，以本节实测记录为准，并为每个响应结构补充一次真机回归验证。
